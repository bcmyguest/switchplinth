## Implementation decisions and deviations

- Compose mounts `${DECISION_WORKSPACE_HOST:-.}` to `/workspace/repos`. The picker lists eligible relative directory paths, rejects traversal/symlinks, and separates disposable SQLite/Qdrant state by canonical repository path. A first open of a Markdown-only repo bootstraps its v1 schema, config, and extraction instructions.
- Compose host ports bind to `127.0.0.1`; the backend maps `host.docker.internal` to the host gateway for Linux local-model connectivity. CORS accepts only `localhost:3000` and `127.0.0.1:3000`. The API has no authentication; remote access is unresolved and not part of the local V0 listener setup.
- Portable schema version `decision/v1` is validated; unknown versions are rejected. A future v1→v2 migration is not implemented and remains a requirement before schema evolution.
- Markdown discovery excludes `.decision/`, `.decision-cache/`, `.tasks/`, `.pytest_cache/`, and standard build/cache directories by default. `.decision/config.yaml` supports additional path-segment exclusions, source-specific `extraction.include` paths such as `.tasks/` (without overriding other ignores), and `max_candidates` (default 50). Excluded evidence remains unresolved for historical provenance; reconciliation filters excluded IDs from mixed-support inferred records and removes safe task-only inferred content, including unselected, unreferenced task-grounded decisions. Current-source inferred references can continue supporting shared entities. Human-reviewed records remain unchanged; scans fail closed when removal would leave selected or referenced task-only options, entities, or relationships unsafe.
- `POST /api/v1/discovery/scan` is the full scan/index rebuild path: it rebuilds SQLite and replaces the Qdrant collection. The SQLite index records `index_version`. Canonical YAML is restored if the synchronous scan raises; this rollback does not protect against abrupt process or host termination.
- Scenario save writes only selection records under `.decision/scenarios/`. AI proposals are previews; applying one writes the same option delta as manual editing.
- Provider embeddings use an optional `embedding_model` on a connection with `capabilities.embeddings: true`; the same LiteLLM embedder is used for Qdrant rebuild and query. Missing model configuration reports `unsupported` and uses deterministic token-hash vectors as an offline fallback. A configured provider failure reports `error` and does not silently switch vectorizers. SQLite and Qdrant remain derived indexes.
- LangGraph is intentionally not used in V0: scan is synchronous and there is no workflow checkpoint, resumability, or human approval pause requiring persisted orchestration state.
- No external provider credentials or remote model endpoint were used; provider interoperability was exercised with the local OpenAI-compatible mock.
- Corrected aliases/claims append asserted records that supersede original and prior human judgments, preserve evidence, validate changed entity references, and remain effective after provider re-extraction.
