## Milestone 3: per-record publication durability

`PortableRepository.save()` writes each serialized YAML record to a unique temporary file in the record's directory, flushes and fsyncs it, then publishes it with `os.replace`. It retains an existing record's ordinary rwx permission bits; new files use normal creation permissions subject to the process umask. Special mode bits such as setuid are not preserved (the prior direct write also clears them). An ordinary exception removes the temporary file. If the process exits before replacement, the old target remains; if it exits after replacement, the new complete target is visible. A pre-replacement process exit can leave a hidden temporary file.

This is a per-record process-crash guarantee. It does not make a scan or provider operation spanning multiple records transactional, coordinate concurrent writers, or promise survival across power loss or storage-cache failure. Keep portable files canonical and derived state rebuildable; no database or workflow framework is selected in advance.

## Invalid generated delta quarantine

A fresh local reproduction showed that correctly anchored selected decisions were still rejected when model-generated `add_relationship` operations referenced unknown entities. Persistence now validates the original candidate first. If the evidence and selection are sound and only option delta validation fails, it validates a copy with empty active deltas, saves that decision only if the copy passes, and stores the exact rejected deltas and validator errors in optional `extraction_review` metadata. The graph/compiler sees only the empty active deltas. The API returns the audit and the UI marks the affected options; validated human edits resolve one audit item at a time. The bundled v1 schema declares the metadata; the overlay schema remains unchanged. This is additive to v1, but old writers that drop unknown top-level fields can lose audit metadata.
